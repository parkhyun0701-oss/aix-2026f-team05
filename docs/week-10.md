## 디버깅 요청 4요소 / Four parts of a debugging request

- 증상 Symptom: 첫 정리 카드에서 [정리하기]를 누르면 정리 뒤에도 카드가 하나 더 남아 보인다(#40 리뷰 의견).
- 재현 Steps: 샘플 북마크 100개 넣기 → 확장 프로그램 새 탭 열기 → 첫 정리 카드에서 [정리하기] 클릭 → 정리가 끝난 뒤 화면 확인
- 기대 Expected: 정리가 끝나면 첫 정리 카드가 사라지고, 결과 안내(12초, [되돌리기])만 보인다. [정리하기]는 다시 누를 수 없다(F06-01·06).
- 실제 Actual: 정리 중 북마크 변경 알림 때문에 화면을 다시 그리면서 두 번째 카드가 남았다. 수정 커밋 `435cd17`(정리 중에는 카드를 다시 그리지 않고, 다시 그리기를 100ms로 묶음)이 올라왔지만 크롬에서 다시 확인하지 않았다.

## 데모 시나리오 초안 / Draft demo scenario

1. 샘플 북마크 100개가 든 크롬에 확장 프로그램을 설치하고 새 탭을 연다. 크롬 북마크가 앱 아이콘 형태로 바로 보인다(F01, F02, F12).
2. 첫 정리 카드에서 [자세히 보기]를 누른다. 북마크별 분류 근거와 "확인 필요" 표시를 보여 준다. 정리 전에는 크롬 북마크가 바뀌지 않는다(F05, F06).
3. [정리하기]를 누른다. 북마크바에 폴더 5개가 생기고 북마크 53개가 옮겨진다. 결과 안내가 12초 동안 [되돌리기] 버튼과 함께 나온다(F07).
4. 내 폴더 줄에 새 폴더가 보이고, 폴더를 누르면 팝업으로 안의 북마크를 보여 준다(F03).
5. [되돌리기]를 누른다. 53개가 원래 자리로 돌아간다(F13).
6. 오래 열지 않은 북마크를 모은 "잊고 있던 북마크" 폴더와 팝업을 보여 준다(F04).
7. 웹 검색창에 검색어를 입력하고 Enter를 누르면 기본 검색엔진으로 검색된다. 주소를 넣으면 그 주소로 바로 이동한다(F11).
